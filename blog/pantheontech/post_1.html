Cómo levanté mi propio blog y lo saqué a internet How I set up my own blog and put it online

El punto de partida The starting point

Quería un sitio propio, servido desde mi propia máquina Linux, sin depender de una plataforma de terceros. Nada de plantillas cerradas: quería controlar cada línea de HTML y CSS, y sobre todo entender qué hay detrás de "publicar algo en internet".

I wanted my own site, served from my own Linux machine, without depending on a third-party platform. No closed templates: I wanted to control every line of HTML and CSS, and above all understand what's behind "publishing something on the internet".

Publicar el sitio Publishing the site

El servidor corre en mi propia infraestructura Linux, expuesto a internet a través de un dominio propio. Antes de abrir nada al exterior, quise asegurarme de que la exposición fuera consciente: qué puertos, qué servicios, y qué pasa si alguien intenta entrar por la puerta de atrás.

The server runs on my own Linux infrastructure, exposed to the internet through a custom domain. Before opening anything to the outside, I wanted to make sure the exposure was deliberate: which ports, which services, and what happens if someone tries to get in through the back door.

Auditoría de seguridad propia My own security audit

Antes de dar el sitio por "terminado" hice mi propia auditoría de seguridad, siguiendo una metodología de pentesting completa sobre mi propio servidor. El primer hallazgo fue el más típico: el puerto SSH estaba expuesto en el puerto por defecto, el 22.

Before calling the site "finished" I ran my own security audit, working through a full pentesting methodology on my own server. The first finding was the most typical one: SSH was exposed on the default port, 22.

A partir de ahí apliqué varias medidas de endurecimiento: 

- Desactivar la autenticación por contraseña (solo claves SSH)
- Restringir el acceso root por SSH
- Cambiar el puerto por defecto del servicio SSH
- Configurar fail2ban para bloquear intentos repetidos

From there I applied several hardening measures: disabling password authentication (SSH keys only), restricting root login over SSH, changing the default SSH port, and setting up fail2ban to block repeated login attempts.

Qué sigue What's next

Como siguiente paso quiero revisar el auth.log con calma para ver si hay rastro de intentos de intrusión previos, y dejarlo como algo que reviso de forma periódica, no solo una vez.

As a next step I want to go through auth.log carefully to check for any trace of previous intrusion attempts, and turn that into something I review periodically, not just once.
